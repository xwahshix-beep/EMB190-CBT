# V6.6: quarter-hour activity shadow experiment

No live BUY thresholds, notification gates, symbol selection or execution code change. Reuses available closed minute rows; no new API or background service. It does not reconstruct the paper's 10-second futures signal. It tests a minute-resolution Spot hypothesis.

Per symbol: accumulate mean quote turnover and trade count by UTC minute modulo 15. Deduplicate timestamps, reject missing/stale windows, exclude the current 5-minute target from calibration. Require elapsed seven days, at least seven observed UTC dates, and 100 samples per phase, all with positive means. These are engineering readiness limits, not statistical sufficiency. Freeze the means at activation; never retrain on the subsequent 28-day observation period. No automatic replacement of the live model.

Normalize each of the 125 minute quote/trade observations by its frozen phase mean relative to the pooled mean; recompute 5/120 minute accelerations and the 24-window trade z-score. Log the original and adjusted values plus both activity flags. The comparator uses the same activity thresholds only; it does not issue an alternate BUY or change liquidity/price requirements. Only the general scanner is instrumented, not manual FastWatch.

Record the first available valid observation each UTC hour per symbol, including neither-active controls. Last 72 hourly samples per symbol retained; export JSON at least every 48 hours to preserve the full four-week study. The export includes frozen model, timestamps, features and per-minute comparison counters. Counters are correlated frames, not independent trades. Missing observations remain missing. Returns use last closed minute reference price and an observed closing price 0–90 seconds after the horizon (5/15/60 min); these are not fills or net profits. A model that reaches expiry requires review, not automatic restart. Delisted/out-of-scope symbols retain previously recorded data; new unavailable outcomes remain missing.

Pre-register evaluation before inspecting future results: compare groups both/raw-only/adjusted-only/neither on the hourly sample, include negative returns and missing observations, report coverage by symbol and day. Do not label raw-only automatically false or adjusted-only automatically a saved opportunity. Define a forward movement threshold in advance, analyze sensitivity, and compare a random/no-activity baseline. Bootstrap by day and symbol rather than treating each minute independently. Store training and validation selection decisions. Never tune on final holdout.

Before any live change, a separate executable-price replay is still required: bid/ask snapshots, signal and delivery times, fees of the actual account on both legs, spread, size-dependent slippage, network/device delay and missed fills. The current export does not contain a full order book, all intraminute paths or every alert event, so it cannot establish executable profitability, stop-first/target-first ordering, or comprehensive missed-move recall. Add prospective bid/ask recording before that test. Test 1/3/10-second latency, measured notification latency, both increasing/decreasing markets, all eligible assets at each time including losers/delistings, and costs stressed above their baseline.

Physical Samsung battery/notification tests still needed: compare current versus shadow version for a matched session on the same network/brightness/universe; measure CPU, storage writes, battery drain and notification delivery. Unit tests use synthetic data to verify correctness only; they do not validate market performance.
